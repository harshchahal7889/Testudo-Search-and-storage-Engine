2   Data Flow — Document Upload & Semantic Search

sequenceDiagram
    participant U as User
    participant API as REST API
    participant AI as AI Module
    participant OL as Ollama
    participant DB as SQLite
    participant OS as Virtual Disk

    Note over U,OS: Document Upload Flow
    U->>API: POST /upload (text file)
    API->>API: Acquire mutex
    API->>AI: Split text into overlapping chunks
    loop Each Chunk
        AI->>OL: Embed chunk (nomic-embed-text)
        OL-->>AI: Vector embedding
        AI->>DB: INSERT embedding + metadata
        AI->>OS: Allocate disk blocks (FAT chain)
        OS->>OS: Write chunk data to blocks
    end
    API->>DB: INSERT document record, set owner ACL
    API-->>U: 201 Created

    Note over U,OS: Semantic Search Flow
    U->>API: GET /search?q="car"
    API->>API: Acquire mutex
    API->>AI: Embed query (nomic-embed-text)
    AI->>OL: "car" → query vector
    OL-->>AI: Query vector
    AI->>DB: Fetch stored embeddings
    AI->>AI: Cosine similarity (Brute / KD / HNSW)
    AI->>DB: ACL check per result
    AI-->>API: Ranked, permitted results
    API-->>U: 200 OK — results (includes "automobile" doc)

3   Data Flow — RAG Question Answering

sequenceDiagram
    participant U as User
    participant API as REST API
    participant AI as AI Module
    participant OL as Ollama
    participant DB as SQLite

    U->>API: POST /ask { question, conversation_id }
    API->>API: Acquire mutex
    API->>AI: Embed question
    AI->>OL: question → vector (nomic-embed-text)
    OL-->>AI: Query vector
    AI->>DB: Retrieve closest permitted chunks
    AI->>DB: Load conversation history
    AI->>OL: Prompt = chunks + history + question (llama3.2)
    OL-->>AI: Generated answer
    AI->>DB: Persist Q&A to conversation history
    API-->>U: 200 OK — answer

6   Concurrency Model

graph TD
    R1["Request 1"] --> MTX["Single Mutex"]
    R2["Request 2"] --> MTX
    R3["Request N"] --> MTX
    MTX -->|"Exclusive Access"| CS["Critical Section\n(Disk + DB + Vectors)"]
    CS --> RELEASE["Unlock"]
💡 Tip A single coarse-grained mutex is used deliberately instead of fine-grained locks. This eliminates all deadlock risk at the cost of some throughput — an acceptable trade-off given the project's scope.
